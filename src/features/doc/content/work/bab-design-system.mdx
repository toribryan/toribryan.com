## Two artefacts, one product

The [Support Agent Dashboard](/work/support-agent-dashboard) shipped as a
25-screen clickthrough: vanilla HTML, CSS and JavaScript, no framework, no build
step. That is the right shape for proving an interaction — it loads instantly and
nothing about it is negotiable with a bundler. It is also the wrong shape for
handing to engineering, because a prototype has no components in it. It has
markup that happens to look like components.

This is the other half: the same product expressed as a library.

Built on **Base UI** primitives with **Tailwind v4** and shadcn conventions,
typeset in Geist. Charts are Recharts; the command palette is cmdk; toasts are
Sonner. Nothing exotic — the interesting decisions are in the token layer, not
the dependency list.

| Group        | Count | What's in it                                                                                                                                                                                    |
| ------------ | ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ui/`        | 21    | Accordion, avatar, badge, button, card, chart, command, dialog, dropdown, input, input group, popover, segmented control, skeleton, sonner, switch, table, tabs, textarea, toggle, toggle group |
| `inbox/`     | 10    | Conversation list and rows, message thread, composer, chat header, side panel, role avatar and badge, command palette, close-conversation dialogs                                               |
| `dashboard/` | 5     | Stat tile, trend chart, source card, compare toggle, report metric layout                                                                                                                       |
| `chrome/`    | 4     | App shell, icon rail, secondary nav, topbar                                                                                                                                                     |

On top of those sit 12 page compositions — Inbox, Knowledge (sources and
content), Settings, and eight report views — each a story in its own right, so a
change to a primitive is visible at page scale immediately rather than at
integration time.

## The token layer is the actual deliverable

The prototype already had a disciplined `tokens.css`: surfaces, chat row states,
a series palette for charts. Rather than redraw those decisions in Tailwind's
vocabulary, the rebuild promotes them into a `@theme` layer under the same names.

```css title="src/index.css"
:root {
  --primary: #c70036; /* the one red that means "primary action" */
  --background: #efeceb; /* app ground — cards float on it, no dividers */
  --surface-nested: #f8f7f6; /* tiles and chart wells inside a white card */
  --sel: #dbd3d1; /* selected chip, filter pill, received bubble */

  /* Inbox rows carry their own scale, because "unread" has to read as
     lighter than the ground while "read" reads as a step darker. */
  --unread: #fdfcfc;
  --chat-read: #e6e1e0;
}
```

Three things fell out of that which I'd keep on any project of this shape:

<Steps>

<Step>
  **Two reds, named apart.** `--primary` (`#c70036`) is for primary actions.
  `--red-deep` (`#b20030`) is the inbox Close button and the live-attempt badge,
  and nothing else. A single `--red` would have collapsed two meanings into one
  swatch and they'd have drifted apart in code anyway.
</Step>

<Step>
  **Role colour is semantic, not decorative.** Student, instructor and admin
  each own a background/foreground pair, and the chart series reuse those same
  hues. An orange line on the Overview chart means the same thing an orange
  badge does in the Inbox.
</Step>

<Step>
  **One elevation.** The content card is the only shadowed surface on a page.
  Nested blocks get `--surface-nested` and a hairline border, never a second
  shadow. It's a rule that survives contact with a component library precisely
  because it's a token, not a habit.
</Step>

</Steps>
