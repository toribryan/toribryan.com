## What I built

A shared Claude Code skills infrastructure that gives designers one command for each phase of the design process. It lives in a single repository that each designer clones and symlinks to their machine, so the whole team works from the same commands and standards.

<SkillsRepoTree />

**A command per phase.** `/write-spec`, `/research-synthesis`, `/ux-copy`, and more: each skill is grounded in our brand goals and product context, so its output stays on-brand and consistent by default.

**A handoff skill at the center.** It generates the handoff directly from prototypes built in Claude Code. The old handoff was one long, polished document; I split it into three Markdown specs, each with one job:

- **Handoff:** an overview of the package, with the prototype and a full feature map.
- **Style guide:** the visual design and the design system elements the feature uses.
- **Test plan:** how each feature should behave, as a functional spec.

Three things changed with it:

- **Markdown is the standard.** Plain text reads well for everyone, screen readers included, and designers spend their time on what the spec says instead of how the document looks.
- **The prototype is the source of truth.** Visual references are Figma links and the prototype itself. A handoff update tool logs every change to the prototype in the release notes, so the specs and the prototype never drift apart.
- **Engineers shaped it.** I refined the format through feedback loops with engineers, keeping the references that actually helped them build and dropping the rest.

**Figma connected to the pipeline.** MCP and Code Connect tie prototypes to real design-system components. From there, an agentic pipeline ingests a PRD, aligns it to our coding standards and design system, and outputs production-ready code.

**A documented protocol around the tooling.** The process is repeatable across the team rather than dependent on any one designer.

## Impact

<TimeSavedChart />

- Cut spec production from 3 days–2 weeks to under 30 minutes, up to 80 hours per handoff cycle returned to design work.
- Reached 100% adoption across the design team, validated with 4 designers across 3 products plus 3 engineers and 1 PM.
- Reduced the friction engineers hit when consuming specs, replacing hand-maintained docs with a consistent structure and automated release notes.
- Kept specs in sync with design by generating them from the source prototype instead of maintaining them separately.

It builds on the RDS v2 design system I overhauled (37 components, 94% fewer card variants), where a v2 card dropped from two weeks to 1.5 days to build, saving roughly 64 engineering hours per component.

I presented the finished process to the organization on July 26, 2026.

## Design system skills

I carried the same approach into [fibo](/fibo), my own design system. Its skills live in the repo next to the code, so anyone working on fibo, or an agent working for them, follows the same steps:

- **`add-component`** adds a component end to end: the source file, stories, the Storybook docs page, catalog metadata and the registry entry. A component isn't done until all of them exist.
- **`figma-drift`** checks the Figma library against the code for drift in color variables, radii and variant properties, and reports where Figma and code disagree. It never fixes either side on its own.
- **`retire-component`** deprecates a component and later removes it: the docs banner and migration notes, a codemod with its tests, the changelogs and the removal release.
