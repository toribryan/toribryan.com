Data table is one table for every list people work through. Selection is
always the first column, every action lives in one toolbar above the rows,
and the same parts hold up from a wide dashboard down to a phone. TanStack
Table works out the rows and keeps the state; Data table draws them in a
native table.

<ExhibitCode label="Usage">

```tsx
import { Badge } from "@/components/ui/badge"
import {
  createDataTableColumnHelper,
  DataTable,
  DataTableContent,
  DataTableFilters,
  DataTableSearch,
  DataTableToolbar,
  useDataTable,
} from "@/components/ui/data-table"

// Outside the component, so the rows aren't worked out again every render.
const column = createDataTableColumnHelper<Member>()
const columns = column.columns([
  column.accessor("name", {
    header: "Member",
    meta: {
      type: "person",
      avatar: (member: Member) => ({
        src: member.photo,
        fallback: member.initials,
      }),
    },
  }),
  column.accessor("status", {
    header: "Status",
    filterFn: "arrHas",
    meta: { type: "status" },
    cell: ({ getValue }) => <Badge variant="success">{getValue()}</Badge>,
  }),
])

export function Members({ members }: { members: Member[] }) {
  const table = useDataTable({
    data: members,
    columns,
    lockedReason: (member) =>
      member.isOwner ? "The workspace owner can't be removed" : undefined,
    initialState: { columnPinning: { start: ["name"], end: [] } },
  })
  return (
    <DataTable
      table={table}
      aria-label="Members"
      noun={{ one: "member", other: "members" }}
    >
      <DataTableToolbar>
        <DataTableFilters
          search={<DataTableSearch aria-label="Search members" />}
        />
      </DataTableToolbar>
      <DataTableContent />
    </DataTable>
  )
}
```

Every row needs an `id`, or pass `getRowId`: selection is kept by id, so it
survives sorting, filtering and paging. Keep `columns` and `data` stable
between renders. The first primary or person column names each row's
checkbox. Every row shows until you give the table a page size, in
`initialState.pagination` or a pagination atom, and put DataTablePagination
in the footer.

</ExhibitCode>
<ExhibitCode label="Column meta">

```ts
type DataTableColumnMeta = {
  type?: "primary" | "text" | "person" | "status" | "numeric" | "actions"
  label?: string // in the Columns menu, filters and cards
  className?: string // on the head and every cell, such as a width
  secondary?: (row: Row) => ReactNode
  avatar?: (row: Row) => { src?: string; fallback: string } | undefined
  icon?: ReactNode

```

</ExhibitCode>
<ExhibitCode label="Props">

| Prop                       | Type                             | Default        | Description                                                                   |
| -------------------------- | -------------------------------- | -------------- | ----------------------------------------------------------------------------- |
| `table`                    | `DataTableInstance`              |                | The table from `useDataTable`.                                                |
| `noun`                     | `{ one: string; other: string }` | rows           | What a row is, for counts and labels.                                         |
| `narrowLayout`             | `"scroll" \| "cards"`            | `"scroll"`     | Under 32rem, keep the table and scroll it, or show a card per row.            |
| `loading`                  | `boolean`                        | `false`        | Shows skeleton rows in place of the body while the data loads.                |
| `empty`                    | `ReactNode`                      | DataTableEmpty | Shown in place of the rows when there are none. `null` leaves the body blank. |
| `showSelectedOnly`         | `boolean`                        | `false`        | Whether the app is showing only the selected rows.                            |
| `onShowSelectedOnlyChange` | `(show: boolean) => void`        |                | Shows Show selected only while rows are selected. The app filters rows.       |

`useDataTable` takes TanStack Table's options for Data table's features,
`data` and `columns` among them, plus `lockedReason`, a function that says
why a row can't be selected.

DataTableFacetFilter and DataTableColumns take a `label` for their button.
A facet filter's defaults to its column's `meta.label`, then its header.

### Search, filters and pages

The table sorts, searches, filters and pages its own rows from its state.

<Exhibit

<ExhibitCode>

```tsx
column.accessor("status", { header: "Status", filterFn: "arrHas" })

// Inside the DataTable, so the hooks can reach the table.
function TableFilterMenu() {
  const table = useDataTableContext()
  const status = useDataTableFacets("status")
  const filters = useSelector(table.atoms.columnFilters, (list) => list)
  const picked = filters.find((filter) => filter.id === "status")?.value

  return (
    <FilterMenu
      fields={[
        {
          id: "status",
          label: "Status",
          options: status.map(({ value, count }) => ({
            value: String(value),
            label: String(value),
            count,
          })),
        },
      ]}
      value={{ status: (picked as string[]) ?? [] }}
      onValueChange={(next) =>
        table
          .getColumn("status")
          ?.setFilterValue(next.status?.length ? next.status : undefined)
      }
    />
  )
}

<DataTableFilters search={<DataTableSearch aria-label="Search members" />}>
  <TableFilterMenu />
</DataTableFilters>
```

### Loading

Set `loading` while the data is on its way. The body shows skeleton rows
shaped like the visible columns, narrow cards show skeleton cards, and the
table is `aria-busy`. Both keep the real rows' height, so nothing jumps when
the data arrives. A hand-written body can render `DataTableSkeleton` itself.

With no rows, the table says so in place of the body. When a search or filter

### In the URL

Sorting, the search, filters and the page can each live in a search param,
so a link opens the same view. `useSearchParamsAtom` writes with
`history.replaceState`, so typing a search doesn't fill the back button. It
starts empty on the server and in the first render, so hydration matches,
and applies the URL's value once mounted.

<Exhibit
  of="data-table.UrlSynced"
  title="URL-synced state"
  description="Sort, page or search and watch the params below the table, and the address bar, change. Reload and the view comes back."
>
<ExhibitCode>

```tsx
const sorting = useSearchParamsAtom("sort", dataTableCodecs.sorting)
const globalFilter = useSearchParamsAtom("q", dataTableCodecs.text)
const columnFilters = useSearchParamsAtom(
  "filters",
  dataTableCodecs.columnFilters
)
const pagination = useSearchParamsAtom("page", dataTableCodecs.pagination(4))

const table = useDataTable({
  data,
  columns,
  atoms: { sorting, globalFilter, columnFilters, pagination },
})
```

The codecs hold up to a hand-edited link: a sort with no direction sorts
up, a column sorted or filtered twice counts once, and a page that isn't a
whole number opens the first.

Selection, column visibility and pinning stay in the table. For rows that
page on a server, set `manualSorting`, `manualFiltering`,
`manualPagination` and `rowCount`, and load the rows the atoms describe.

</ExhibitCode>
</Exhibit>

### Bulk actions

Every table's bulk actions read in one order: your actions, then More, then
Delete behind a divider. An action that works on one row stays in place,
dimmed, while more are selected. They act on every selected row, including
any a search or filter hides, and the toolbar says how many those are.

## Reading and owning state

The component that calls `useDataTable` doesn't re-render when the state
changes; each part subscribes to what it shows, so ticking a row re-renders
that row and the toolbar, not the table. To read state there, pass a
selector, `useDataTable(options, (state) => state.rowSelection)`, and read
`table.state`, or use `table.Subscribe`. Act on the selection with
`table.getSelectedRowIds()` and `table.resetRowSelection()`. The selection
holds every selected row still in the data: ids a refetch drops leave it,
but rows a search or filter hides stay selected, and the toolbar, the
announcement and DataTableSelectionCount say how many, as in “5 members
selected, 2 hidden by filters”. Bulk actions act on all of them, hidden
ones included, and Delete's description gives the count. The header
checkbox speaks for the page; Select all matching adds every row the
filters let through and keeps the hidden ones; Clear and Escape clear
everything. With `manualPagination`, ids on other pages stay, since the app
owns those.

### What it registers

`dataTableFeatures` registers only what Data table uses, so a table carries
nothing else: sorting (`text`, `alphanumeric`, `basic` and `datetime`
comparators), column and global filtering (`includesString`, `equals` and
`arrHas`), faceted unique values, pagination, row selection, column
visibility and column pinning. Grouping, expanding, resizing, ordering and
row pinning are left out.

## Migrating to the table API

The `rowIds`, `totalCount`, `value`, `defaultValue` and `onValueChange`
props, `useDataTableSelection`, and hand-written `DataTableRow`,
`DataTableCell` and `DataTableHead` are deprecated in fibo 0.2.0 and removed
in 0.3.0. Until then they run on the same TanStack table as the new API,
built from `rowIds` with selection only, so they behave as they did. A
codemod lists every use with its file and line; it changes nothing, since
writing column definitions needs a person.

```sh
pnpm dlx jscodeshift --parser tsx --dry \
  -t https://fibo.toribryan.com/codemods/data-table-legacy-api.js src
```

## Anatomy

A native table inside a box that measures its own width. The toolbar sits
above it, and the cards replace it on a narrow screen. Both draw the rows
from the same TanStack row model. The narrow Filters button opens a
sheet, `data-table-filters-sheet`, holding the sort and filter controls.
